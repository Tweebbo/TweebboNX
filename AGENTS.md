# Tweebbo Switch: notes for contributors and AI agents

Read `README.md` and `../Tweebbo-3DS/AGENTS.md`. This is the showcase proof of concept of the
native Nintendo Switch client of Tweebbo; it plays in the same world as `tweebbo.lol`, the 3DS
and the Vita.

- Everything in this repository (code, comments, documentation, interface and commit messages)
  is written in English.
- **Protocol parity**: the protocol must match `../Tweebbo-Vercel/server/src/proto.rs` (version 6,
  `HELLO` with `platform = 1`, capability bits and the trailing device byte `2` = Switch). The
  s2c `DEVICE` (140) message announces each player's native device; older clients ignore it.
  Keep compatibility with `../Tweebbo-3DS`.
- **Shared core**: `source/` (except `source/nx/`) is the portable C11 core, identical to the
  Vita client (`../Tweebbo-Vita`). Fix shared bugs in both repositories or, better, in
  `../Tweebbo-3DS` first. `source/gen/` is generated by `tools/pack.py` of the 3DS repo: never
  edit it by hand.
- **Platform rules**:
  - Never write synchronously to `sdmc:/` from the render thread; use the RAM log ring
    (`source/nx/log.c`).
  - Keep the tuned `SocketInitConfig` in `source/nx/conn.c` (prevents `ENOBUFS`).
  - Never poll the `ts` temperature sensor service or override system clocks.
  - Touch and pad are read in the same frame (do not swallow the first A after a touch).
- **Verification**: `./build.sh` must produce `out/tweebbo.nro` from a clean tree. Run the
  cross-play check against a local hotel with the updated server:
  `TWEEBBO_URL=ws://127.0.0.1:8092 node ../Tweebbo-Vercel/tests/device-announcement.mjs`.
- Never log, show or commit player tokens (`token-*.txt`), private codes or production data.
